# Dark Mode and Settings App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Settings app with Light / Dark / Auto appearance, and give the whole portfolio a dark look.

**Architecture:** `src/lib/theme.js` holds pure helpers (read/write the stored preference, resolve it against the system setting, apply it as a `dark` class on `<html>`). `ThemeProvider` in `src/hooks/useTheme.jsx` owns the preference state, applies it, and follows system changes under Auto; an inline script in `index.html` applies the same rule before first paint. Every component gets Tailwind `dark:` classes, enforced by a guard test whose pending list shrinks task by task.

**Tech Stack:** React 19, Tailwind CSS v4 (`@custom-variant dark`), Vitest + Testing Library, jsdom.

**Spec:** `docs/superpowers/specs/2026-10-02-dark-mode-design.md`

## Global Constraints

- No new dependencies. No Apple artwork (our own gear icon).
- Site copy is in English.
- Default preference is `'auto'`; storage key `'theme'`; values `'light' | 'dark' | 'auto'`.
- Dark mode is the `dark` class on `document.documentElement`, plus `style.colorScheme`.
- Dark palette exactly as the spec's "Dark palette" table. Small grey text on dark surfaces is never darker than `neutral-400`.
- Not themed: app icons, photos, project screenshots, the Resume PDF itself.

## Review Focus

- `localStorage` that throws on both read and write (Safari private mode) must not crash the app or the inline script (tests in Task 1 and Task 3).
- Switching from Auto to Light while the system is dark must stop following system changes (test in Task 2).
- A stored junk value (e.g. `'purple'`) must behave like Auto in both `theme.js` and the inline script (tests in Task 1 and Task 3).
- The Settings radios must reflect a preference set before the app opened, for example one loaded from storage (test in Task 4).
- Text inside dark windows must stay readable. The guard test enforces that a `dark:` counterpart exists, and the screenshots in Task 9 check the result.

### Task 3: No-flash script and dark CSS

**Files:**

- Create: `src/lib/themeScript.test.js`

**Interfaces:**
- Consumes: `THEME_STORAGE_KEY`, `SYSTEM_DARK_QUERY` (Task 1).

`index.html` gets this inline script as the last child of `<head>`. It is exact, because the test runs it:
```html
<script>
  try {
    var preference = localStorage.getItem('theme')
    var dark = preference === 'dark' || (preference !== 'light' && matchMedia('(prefers-color-scheme: dark)').matches)
    document.documentElement.classList.toggle('dark', dark)
    document.documentElement.style.colorScheme = dark ? 'dark' : 'light'
  } catch (error) {}
</script>
```

`src/index.css`: add `@custom-variant dark (&:where(.dark, .dark *));` after the import. Add dark scrollbar overrides: `.dark ::-webkit-scrollbar-thumb` uses `rgb(255 255 255 / 0.25)`, `0.4` on hover. Inside the existing `@supports` block, `.dark *` gets `scrollbar-color: rgb(255 255 255 / 0.25) transparent`.

### Task 5: Guard test for dark counterparts

**Files:**
- Create: `src/test/darkMode.test.js`

**Interfaces:**
- Produces: `PENDING`, an array of repo-relative file paths. Later tasks remove entries from it.

Rule, applied to every string or template literal in each non-test `src/**/*.jsx` file:
- A literal holding a light background token must also contain `dark:bg-`. A light background token is a whitespace-separated class whose last segment (after the final `:`) is exactly `bg-white`, `bg-gray-50`, `bg-gray-100` or `bg-gray-200`, and whose prefix doesn't include `dark:`.
- A literal holding a `text-gray-<n>` token (same prefix rule) must also contain `dark:text-`.

Use `import.meta.glob('../**/*.jsx', { query: '?raw', import: 'default', eager: true })`, filter out `.test.jsx`, and match literals with `/(['"`])((?:\\.|(?!\1)[\s\S])*?)\1/g`.

  - `it('lists only files that still need work')` expects every `PENDING` file to still have a violation, so stale entries get removed.
  - Initially set `PENDING` to exactly the files that violate today. Find them by running the test with `PENDING = []` and copying the reported list. `SettingsApp.jsx` must not be in it.
