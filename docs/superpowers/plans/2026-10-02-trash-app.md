# Trash App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Finder-style "Trash" app that lists unreached dreams in a sidebar and shows the selected dream's details, with Put Back / Empty humor.

**Architecture:** Dream content lives in `src/data/dreams.js`. `src/apps/TrashApp.jsx` renders a top bar, a grouped sidebar and a detail pane; a Tailwind container query switches it to a list → detail flow when the window is narrower than 520px. The app is registered last in `src/data/apps.js` with `dockGroup: 'end'`; the Dock draws a divider before it, and `AppIcon` gains a tile-less Trash glyph.

**Tech Stack:** React 19, Tailwind CSS v4 (built-in container queries), motion, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-02-trash-app-design.md`

## Global Constraints

- Site copy is in English; all copy strings below are exact.
- No Apple artwork: the Trash icon is our own SVG.
- No images inside the window; SVG glyphs only.
- Put Back and Empty never change the data.
- Narrow breakpoint: the app's own container width below 520px (`@[520px]` container query), not device type.
- Desktop window: `size: { width: 720, height: 480 }`, `initialPosition: { x: 240, y: 60 }`.

## Review Focus

- Selecting a different dream after clicking Put Back must clear the "Still on the list — working on it." message (test in Task 3).
- While the Empty alert is open, Tab must not move focus out of it, since it has a single button (test in Task 4).
- A not-yet dream shows "—" for Date Deleted and no "What came instead" section (test in Task 3).
- Going back from detail to list on narrow layouts must focus the dream that was open, so keyboard users don't lose their place (test in Task 3).
- Long titles must truncate in the sidebar rather than wrap or overflow (manual check in Task 6).

### Task 3: TrashApp — sidebar, detail, Put Back, narrow flow

**Files:**
- Create: `src/apps/TrashApp.jsx`, `src/apps/TrashApp.test.jsx`

**Interfaces:**
- Consumes: `dreams` from Task 1.
- Produces: `export default function TrashApp()` (no props). Root element carries `data-testid="trash"` and `data-view="list" | "detail"`.

Structure and copy:
- Root: `@container` and `h-full`, flex column, white background.
- Top bar: `Trash — {dreams.length} dreams` on the left; an "Empty" button on the right (wired in Task 4).
- Sidebar: `<nav aria-label="Dreams">` with two groups, headed "Not Yet" and "No Longer Possible". Each dream is a `<button data-dream-id={id}>` with a small document glyph and a `truncate` title; the selected one has `aria-current="true"`.
- Detail: an "‹ Trash" back button (hidden at `@[520px]`), then an `h2` title and a status badge ("Not yet" amber / "No longer possible" grey). Then a `<dl>` with rows Where → `Dreams › {category}`, Date Added → `added`, Date Deleted → `deleted ?? '—'`. Then the story paragraph. When `instead` exists, an `h3` "What came instead" and its paragraph. Put Back at the bottom right.
- Put Back, not-yet: enabled; click shows "Still on the list — working on it." in an `aria-live="polite"` region.
- Put Back, no-longer-possible: `disabled`, with the visible caption "The original location no longer exists."
- State: `selectedId` (initially `dreams[0].id`), `view` (initially `'list'`), `putBack` (boolean). Selecting a dream sets `selectedId`, sets `view` to `'detail'` and resets `putBack`. "‹ Trash" sets `view` to `'list'` and focuses `[data-dream-id=selectedId]`.
- Visibility via container query: below 520px, the sidebar is hidden when `view` is `detail` and the detail is hidden when `view` is `list`; at `@[520px]` and up, both always show (sidebar about 200px wide, its own scroll; detail scrolls independently).

### Task 4: Empty alert

**Files:**
- Modify: `src/apps/TrashApp.jsx`, `src/apps/TrashApp.test.jsx`

**Interfaces:**
- Consumes: `TrashApp` from Task 3.

Spec values: `role="alertdialog"`, `aria-modal="true"`, labelled by the title "Are you sure you want to permanently erase these dreams?" and described by "Some dreams are worth keeping, even the ones that didn't happen.", with one button, "Keep Them". It is centred over the app content (absolute, inside the root, which becomes `relative`), with a dim backdrop. Opening focuses "Keep Them". "Keep Them" or Escape closes it and focuses "Empty". Tab and Shift+Tab are prevented while it is open.

- [ ] **Step 1: Write the failing tests**

```js
it('asks before emptying and keeps everything', () => {
  render(<TrashApp />)
  const empty = screen.getByRole('button', { name: 'Empty' })
  fireEvent.click(empty)
  const alert = screen.getByRole('alertdialog', { name: 'Are you sure you want to permanently erase these dreams?' })
  expect(alert).toHaveAccessibleDescription("Some dreams are worth keeping, even the ones that didn't happen.")
  const keep = within(alert).getByRole('button', { name: 'Keep Them' })
  expect(keep).toHaveFocus()
  fireEvent.click(keep)
  expect(screen.queryByRole('alertdialog')).toBeNull()
  expect(empty).toHaveFocus()
  expect(within(screen.getByRole('navigation', { name: 'Dreams' })).getAllByRole('button')).toHaveLength(4)

it('closes the alert with Escape', () => {
  render(<TrashApp />)

  fireEvent.keyDown(screen.getByRole('alertdialog'), { key: 'Escape' })
  expect(screen.queryByRole('alertdialog')).toBeNull()
  expect(screen.getByRole('button', { name: 'Empty' })).toHaveFocus()

it('keeps focus inside the alert on Tab', () => {
  render(<TrashApp />)
  fireEvent.click(screen.getByRole('button', { name: 'Empty' }))
  const keep = screen.getByRole('button', { name: 'Keep Them' })

  expect(keep).toHaveFocus()
```
